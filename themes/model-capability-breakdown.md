# 主题：新模型能力拆解（Model Capability Breakdown）

## 主线论点

> **前沿模型发布的真正信号不在"它做到了什么"（demo），而在"它的能力曲线长什么形状 + 它选择以什么形态分发"。一个可复用的拆解模板比追每一个模型卡更有杠杆——它让你在 30 分钟内就能判断这次发布是新闻还是范式。**

这个主题的作用是为本仓库的**模型发布类信号**建立一套统一的解剖结构。每出一个新模型，按这套模板填，结果就可纵向对比、可累积。

## 拆解模板：七维 × 三视角 × 四素材

### 1️⃣ 七维能力坐标（纵向）

每个新模型在七个维度上都有一个位置。**不要每次都重写定义，只填位置。**

| 维度 | 衡量指标（择优） | 该填什么 |
|------|----------------|---------|
| **编码** | SWE-bench Verified, FrontierCode, Aider, CursorBench | 1-2 个 benchmark 的得分 + 曲线形状 |
| **推理** | MATH, GPQA, ARC-AGI | 得分 + 思考预算敏感度 |
| **视觉 / 多模态** | MMMU, ChartQA, 端到端 demo（如 Pokémon FireRed） | 哪些任务能"裸眼"完成 |
| **智能体** | tool use, computer use, OSWorld, multi-turn agent benchmarks | 多步任务的成功率 + 平均步数 |
| **长上下文** | NIAH, RULER, 1M token retrieval | 上下文窗口 + 检索准确率 |
| **成本 / 延迟** | $/task, tokens/sec, p50/p99 latency | 单任务平均成本 + 曲线斜率 |
| **安全 / 可控性** | red team report, jailbreak rate, refusal rate | 触发护栏的场景 + 误报率 |

**七维不是要面面俱到地填**，而是**优先填"和上一代差异最大"的那 2-3 维**——这就是该模型真正的能力增量。

### 2️⃣ 三类对比视角（横向）

| 视角 | 问题 | 输出 |
|------|------|------|
| **同期对比** | 同时段对手在干什么？ | 当下的 capability frontier 散点图 |
| **代际对比** | 同家族上一代 → 这一代曲线 | 那个家族的进步速率 |
| **Pareto 前沿** | 成本/性能曲线在哪一段被推动？ | 哪些能力变便宜了、哪些没动 |

**Fable 5 例子**：同期对比里 Fable 5 显著领先 GPT-5.5 和 Opus 4.8（编码维度）；代际对比里 Opus 4.8 → Fable 5 在 FrontierCode 上 ~3× 跃升；Pareto 前沿里 $5-$20 区间被向上推动，$2-$5 区间没动。

### 3️⃣ 四种证据素材（按可信度排序）

| 素材 | 可信度 | 用法 |
|------|-------|------|
| **第一方 blog / model card** | 中 | 摘原话、标关键引述。**绝不直接当事实陈述**——这是营销 |
| **第一方 benchmark 图表** | 中 | 提取数值，但标注"厂商自报"。注意子集（如 FrontierCode "Diamond" 50 题）影响可比性 |
| **真实任务 demo** | 高（可观察） | 太阳系模拟、Pokémon 通关——记录任务复杂度和约束（"仅凭视觉、无地图"是关键限定词） |
| **第三方独立评测** | 最高 | 等 30-60 天的 LMSYS Arena、SWE-bench Verified、Aider 等，回填到 signal 的"二次回访" |

**关键纪律**：发布当天，第三方评测还没有。**这时候写 signal 必须明确标注"待 +30 天交叉验证"**，不要把第一方口径写成确定事实。

### 4️⃣ 第四视角：发布形态本身（容易遗漏，但是最大信号源）

这一层往往被忽略，但**结构性变化最常出现在这里**：

- **SKU 形态**：单 SKU / 双 SKU / 多档思考预算 / 同模型不同护栏
- **定价机制**：包月 / 按量 / 信用额度 / 按思考时长（如 Fable 计入"plan limits"或"usage credits"）
- **访问门槛**：公开 API / 企业审批 / 出口管制
- **安全声明**：从"我们减缓风险"演化到"这是世界最强 + 我们提供护栏"——**话术变化本身就是信号**
- **演示选材**：厂商挑哪些 demo 来展示，揭示了他们觉得"对外讲故事最有效"的能力是什么

Fable/Mythos 5 的真正信号——双 SKU——就是在这一层。如果只看七维能力，会漏掉。

## 拆解模板：一页填空版

把这段当骨架，每次新模型发布复制一份到对应 signal 里：

```markdown
## 七维能力位置
- 编码：[数值 + 曲线形状]
- 推理：[...]
- 视觉/多模态：[...]
- 智能体：[...]
- 长上下文：[...]
- 成本/延迟：[...]
- 安全/可控性：[...]

## 三视角对比
- 同期：vs [对手] 在 [维度] 上 [领先/持平/落后]
- 代际：上一代 [模型名] → 这一代，[维度] 跃升 [幅度]
- Pareto：[$X-$Y] 区间被向上推动 / [$A-$B] 区间持平

## 发布形态变化
- SKU：[...]
- 定价：[...]
- 访问门槛：[...]
- 安全话术：[变化趋势]
- 演示选材：[厂商挑了什么，没挑什么]

## 真正的结构性信号（最多 2 条）
1. [...]
2. [...]

## 待 30/90/180 天回访的开放问题
- ...
```

## 跨信号原则（暂列，待更多 signal 沉淀后扩展）

1. **形态变化 > 分数变化**：榜单第一名 6 个月就会被超过，发布形态变化（双 SKU、按思考预算计费）能定义一整个时代
2. **曲线形状 > 单点数值**：max 档 31% vs 11% 是表象，"还在涨 vs 已撞顶"才是判断
3. **第一方口径有半衰期**：所有厂商自报数字默认 30-90 天有效，过期需要第三方交叉验证才能继续引用
4. **演示选材是泄露的内部判断**：厂商选 Pokémon FireRed 而不是某个 enterprise demo，说明他们觉得"视觉 agent"是最强的市场化故事——这本身是信号
5. **安全话术的演化是隐藏时间线**："我们减缓风险" → "我们提供护栏" → "我们提供两个 SKU 你选" —— 这条话术演化曲线值得单独拉一条 theme
6. **能力维度的对手不是另一个模型，是开源谱系**：前沿模型每代领先开源 ~12 个月；评估今天闭源模型的真正问题是"它哪些能力 12 个月后开源会追上"

## 开放问题（持续追踪）

1. **"双 SKU"会被几家跟进？**（见 [signal Fable/Mythos 5](../signals/2026-06-09-anthropic-fable-mythos-5.md) 90 天回访）
2. **测试时算力可扩展性的曲线形状**会不会成为 benchmark 报告的标配——而不是只报 max 档分数？
3. **真实任务 demo 的标准化**有没有可能（如 Pokémon-as-benchmark）——目前每家挑自己的 demo，无横向可比
4. **"裸眼"/"仅凭视觉"这类限定词**值得拉一条独立观察轴：它们经常埋藏关键信息
5. **思考预算计费**的统一单位是否会出现（USD/task、tokens-of-thought）——影响 cost 维度的可比性
