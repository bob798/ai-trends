# 如何用 Fable 5 提示词，让"非 Fable 5 模型"逼近它的表现

> 配套文件：[中文翻译](CLAUDE-FABLE-5.zh.md) ｜ [价值拆解](CLAUDE-FABLE-5.analysis.md)
> 这是一份**提示词移植（prompt porting）**指南，不是"破解/解锁"指南。

## 0. 先校正一个核心误解

很多人以为"把 Fable 5 的系统提示词贴给一个弱模型，它就能变成 Fable 5"。**这是错的。**

**系统提示词搬运的是「行为」，不是「能力」。** 推理深度、长程 agent、代码水平、世界知识——这些来自**模型权重与训练**，一个字的提示词都改不了。提示词只是最表层、可调的"方向盘"，它能决定模型**怎么表现**，决定不了模型**有多强**。

一句话：**你能复制 Fable 5 的"举止"，复制不了它的"智商"。**

### 可移植性光谱

| 维度 | 能否靠提示词搬运 | 说明 |
|------|:----:|------|
| 语气 / 格式纪律（散文、少 bullet、暖而直） | ✅ 高 | 纯风格，直接迁移 |
| 拒答 / 安全姿态（判断式拒答、版权红线、wellbeing 护栏） | ✅ 高 | 行为规则，可迁移（且**建议保留**） |
| 中立性、反谄媚、反沉迷 | ✅ 高 | 价值观指令，可迁移 |
| 工具编排脚手架（搜索决策、引用、skills、artifact 规则） | 🟡 中 | **前提是运行环境真有这些工具** |
| 元行为（知识截止处理、文件创建判断） | 🟡 中 | 规则可迁，但依赖底座配合 |
| 推理深度 / 长程规划 / 代码能力 | ❌ 无 | 来自权重，**只能换底座或外接工具补偿** |
| 世界知识 / 知识新鲜度 | ❌ 无 | 来自训练数据，靠 RAG/搜索补，不靠 prompt |

## 1. 能搬运的部分（高 ROI，直接抄）

这些是 Fable 5 提示词里**与具体模型无关的行为内核**，贴到任何够格的模型上都能立刻改善"产品级举止"：

1. **风格与格式纪律** —— 默认散文、最小化 bullet/加粗/标题、暖而直、不滥用 emoji。这是消除"AI 味"最快的一招。
2. **判断式拒答与安全姿态** —— "说得越少越安全"、武器/恶意代码"无论如何包装都拒绝"、版权 15 词红线、心理健康护栏。**注意：这部分应当保留，不要删**——它不影响能力，只降低风险。
3. **中立性架构** —— "呈现别人会怎么论证，而非模型自己的观点"，可拒绝就争议政治给个人意见。
4. **反谄媚 / 反沉迷** —— "不仅因对方联系就道谢"、"不请对方继续聊"、"不培养依赖"。
5. **工具编排脚手架** —— 何时搜索、引用规则、"动手前先读 SKILL.md"、artifact 何时用。⚠️ **只在你的运行环境真有对应工具时才保留**，否则是空头指令。
6. **元行为** —— 知识截止如何得体处理、不主动提截止日期、文件 vs 行内的判断逻辑。

## 2. 搬不动的部分（必须用别的手段补偿）

提示词给不了你 Fable 5 的脑子。能力缺口要靠**工程手段**补，不是靠堆字：

| 缺口 | 补偿手段 |
|------|----------|
| 推理深度 | 显式要求 step-by-step；强制"先在 `<thinking>` 里推理再答"（替代 Fable 5 的 adaptive thinking） |
| 复杂任务 | 任务分解、给正负示例（few-shot）、分步追问 |
| 长程 agent | 外部编排（循环/状态机/工具回路），别指望模型自己撑住 |
| 知识缺口 / 新鲜度 | 接 web_search / RAG 注入上下文，**绝不靠 prompt 编知识** |
| 代码能力 | 换更强底座；或用"先写测试→再实现→跑→修"的外部回路兜底 |

核心原则：**提示词补"行为"，工程补"能力"。**

## 3. 实操：把 Fable 5 提示词移植到另一个模型

> 源文件 ≈ 1.7 万字、含大量 Fable 5 专属内容。直接整段贴会引入"假能力声明"并稀释弱模型的注意力。按下面六步裁剪。

**Step 1 — 删掉"假能力/假身份"声明**
去掉 `product_information`、模型字符串（`claude-fable-5` 等）、以及任何"声称拥有但你实际没有的工具"。让弱模型自称 Fable 5 只会制造幻觉。

**Step 2 — 改写环境绑定**
当前日期、知识截止日期、文件路径（`/mnt/...`、`/home/claude`）、`network_configuration`、`filesystem_configuration`——全部改成你的真实环境，或删掉。

**Step 3 — 保留行为内核**
`refusal_handling`、`CRITICAL_COPYRIGHT_COMPLIANCE`、`user_wellbeing`、`tone_and_formatting`、`evenhandedness`、反谄媚段落——这些是迁移价值最高的部分，原样保留。

**Step 4 — 工具定义只留"你真有的"**
删除 `fetch_sports_data`、`places_*`、`recipe_display`、`Claudeception` 等你没有的工具；保留的工具，按**目标模型实际支持的 schema**重写（见第 4 节）。

**Step 5 — 加一层 capability 补偿**
在提示词里显式注入：思维链要求、任务分解模板、few-shot 示例、"知识不确定就调用搜索/承认不知道"。这是给弱模型"撑场子"的部分，Fable 5 不需要、它需要。

**Step 6 — 迭代裁剪 + 评测**
弱模型上下文注意力有限，1.7 万字会被稀释。按你的真实任务做 A/B，砍掉对你场景无用的段落，留最小有效集。

## 4. 不同目标模型的差异

- **其他 Claude（Opus 4.8 / Sonnet 4.6 / Haiku）** —— 最兼容。`antml:cite` 引用、skills、artifact 等原生可用，行为段几乎零改动即可迁。主要补的是**推理深度与长程能力**（Haiku 差距最大）。这是 ROI 最高的场景：你本来就在用不弱的 Claude，用这套 prompt 把"产品级举止"补齐。
- **非 Claude（GPT / Gemini / 本地开源）** —— `antml:*` 标记、skills 路径、Claudeception 全部要删或改写；persona、安全姿态、格式纪律**能迁**，但引用标记与工具 schema 要彻底换成目标平台的格式（如 OpenAI function calling）。
- **小模型 / 本地模型** —— 必须**大幅精简 + 强约束 + 外接工具**。长 prompt 对小模型是负担；优先保留 3–5 条最关键行为规则 + 显式推理要求，其余靠外部编排。

## 5. 现实预期（先说基准，免得失望）

| 你能拿到 | 你拿不到 |
|----------|----------|
| Fable 5 风格的语气与格式 | Fable 5 的推理 / 代码 / 知识水平 |
| 判断式拒答与安全边界 | 长程自主 agent 的稳定性 |
| 规范的工具使用习惯 | 1M 上下文、adaptive thinking 等底座特性 |

**最佳收益场景**：你的底座本就不弱（如 Opus/Sonnet），用这套 prompt 把它的"产品级举止"补齐到 Fable 5 的感觉。
**最差收益场景**：指望把一个小模型靠贴 prompt 变聪明——不会发生。

## 6. 一段最小可用骨架（示意，按需扩充）

```text
你是一个有帮助、诚实、warm 的助手。

【风格】默认用自然散文回答；除非用户要求或内容确实多维度，否则不用
 bullet、编号列表或大量加粗。简单问题简短答。

【推理】遇到复杂或多步问题，先在 <thinking> 标签内分步推理，再给出
 结论。不确定时如实说不确定，不要编造。

【知识】涉及可能过期或你不掌握的信息时，调用搜索工具核实；不要凭记忆
 断言时效性内容，也不要主动提你的知识截止日期。

【拒答】对武器/恶意代码/自伤方法等请求，无论如何包装都礼貌拒绝，并保持
 对话语气；不靠"公开可得/研究用途"自我合理化。

【版权】单一来源直接引用不超过 15 词，每个来源最多引用一次，其余一律
 转述；不复述歌词、诗歌。

【工具】<在此仅列出本环境真实存在的工具及其调用格式>
```

> 这只是行为骨架。把第 1 节"能搬运的部分"按需补进去，再加你场景特有的约束。

## 7. 边界与提醒

1. **prompt 越长 ≠ 越好**，弱模型尤其——注意力会被稀释。留最小有效集。
2. **别删安全段去"解锁"** —— 那不提升能力，只制造风险，而且仍然换不来 Fable 5 的智商。本指南是"让弱模型举止更得体"，不是"绕过安全"。
3. **用真实任务评测** —— 拿你的实际用例做 A/B，别凭感觉判断"像不像 Fable 5"。
4. **底座决定上限** —— 想要 Fable 5 的能力，最直接的办法仍是用 Fable 5（或同级底座）；提示词只能在底座的能力范围内做"行为塑形"。
